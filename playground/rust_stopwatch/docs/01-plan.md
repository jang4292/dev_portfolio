# 기획서 — Rust GUI 스톱워치

> 작성일: 2026-11-13 · 상태: 1차 구현 완료

## 1. 배경과 목적

- `playground/`는 학습용 미니 앱을 모아 두는 공간이다.
- Rust 언어를 처음 접하는 사람이 **작동하는 작은 프로그램**을 통해
  Rust의 핵심 개념(소유권, 빌림, `Option`, 구조체, 모듈)을 체험하는 것이 목적이다.
- 터미널 입력 방식 대신 **데스크톱 GUI 창**을 선택했다.
  스톱워치는 실시간으로 변하는 화면이 핵심이므로 GUI가 더 적합하다.

## 2. 요구사항

### 기능 요구사항

| ID | 기능 | 설명 |
|---|---|---|
| F-1 | 시작 | 측정을 시작한다 |
| F-2 | 일시정지 | 측정을 멈추되 누적 시간은 유지한다 |
| F-3 | 재개 | 일시정지 지점부터 이어서 측정한다. 정지한 동안의 시간은 포함하지 않는다 |
| F-4 | 초기화 | 측정을 중지하고 0으로 되돌린다 |
| F-5 | 시간 표시 | `시:분:초.밀리초` 형식. 24시간이 지나도 0으로 되돌아가지 않는다 |

### 비기능 요구사항

| 항목 | 내용 |
|---|---|
| 플랫폼 | macOS · Windows · Linux 데스크톱 |
| 학습성 | 초보자가 읽을 수 있도록 주석과 문서를 함께 제공 |
| 정확성 | 프레임 카운트가 아닌 실제 경과 시간(`Instant` 차이)으로 계산 |
| 테스트 | 시간 로직은 실제 대기 없이 단위 테스트로 검증 가능해야 함 |

### 범위 제외 (1차)

- 랩 타임 기록
- 측정 기록 저장 (창을 닫으면 상태는 사라짐)
- 한글 UI (egui 기본 글꼴이 한글을 포함하지 않아 영문 버튼 사용)

## 3. 기술 선정

| 선택 | 이유 |
|---|---|
| Rust 2021 edition | 학습 대상 언어 |
| `eframe`/`egui` 0.31 | 순수 Rust GUI. 설정이 적고 런타임 의존성이 거의 없어 입문용으로 적합 |
| `std::time::Instant` | 단조 시계(monotonic clock)라 시스템 시각 변경에 영향받지 않음 |
| 외부 크레이트 최소화 | 의존성은 `eframe` 하나만 사용 |

### 검토했던 대안

- **터미널(CLI) 방식**: 구현은 가장 단순하지만 실시간 갱신 UI 학습에 부적합하여 제외.
- **Tauri**: 웹 기술 혼합으로 Rust 학습 비중이 줄어들어 제외.
- **iced / slint**: 훌륭한 대안이지만 egui가 즉시 모드(immediate mode)라 코드량이 가장 적음.

## 4. 설계

### 구조

```text
main.rs       ── UI 계층: 창, 버튼, 시간 문자열, 화면 갱신
stopwatch.rs  ── 로직 계층: 측정 상태(순수 로직, UI 무관)
```

UI와 시간 로직을 분리한 이유:
- `Stopwatch`는 GUI 없이 단위 테스트할 수 있다.
- 나중에 CLI나 다른 GUI로 바꿔도 로직을 재사용할 수 있다.

### 핵심 상태 모델

```text
Stopwatch {
    accumulated: Duration,         // 완료된 구간들의 누적 시간
    started_at: Option<Instant>,   // Some = 측정 중, None = 정지
}
```

- **일시정지**: 현재 구간 길이를 `accumulated`에 더하고 `started_at`을 `None`으로.
- **재개**: `started_at`에 새 시각 기록. 정지해 있던 시간은 자연히 빠진다.
- **경과 시간**: `accumulated + (지금 − started_at)`. 표시할 때마다 계산하므로 오차가 누적되지 않는다.

### 테스트 전략

모든 메서드가 `Instant::now()`를 내부에서 호출하는 대신 **시각을 인자로 받는다**
(`start_at(now)`, `elapsed_at(now)`). 덕분에 테스트에서 가짜 시각
(`기준 + Duration::from_secs(n)`)을 주입해 실제 대기 없이 검증한다.
