# 작업 정리 — 결정 사항과 Q&A

프로젝트를 만들며 논의한 내용과 결정을 기록합니다.

## 1. 진행 경과

| 단계 | 내용 |
|---|---|
| 초안 | 터미널(CLI) 스톱워치로 제안 |
| 방향 전환 | 그래픽 작업 포함 여부 확인 → **데스크톱 GUI**로 확정 |
| 구현 | `eframe`/`egui` 기반 GUI + 로직 분리 + 단위 테스트 |
| 검증 | `cargo fmt --check` · `cargo test`(4개 통과) · `cargo run` 창 실행 확인 (macOS, Rust 1.100.0) |
| 문서화 | README(학습 안내) + docs(기획·가이드·정리) |

## 2. 주요 결정과 이유

### GUI 방식 선택

처음 제안한 터미널 방식은 "빠르게 만들 수 있는 학습용"이라는 임의 가정이었다.
스톱워치는 실시간으로 변하는 화면이 본질이므로 GUI가 학습 목적에도 더 맞다고 판단해 전환했다.

### UI와 로직 분리

`stopwatch.rs`는 egui를 전혀 모른다. 시각을 인자로 받는 설계
(`elapsed_at(now)`) 덕분에 GUI 없이, 실제 대기 없이 테스트할 수 있다.

### 영문 버튼 사용

egui 기본 글꼴에 한글이 포함되지 않아 1차에서는 영문(Start/Pause/Reset)을 사용.
한글화는 글꼴 등록과 함께 연습 과제로 남김.

## 3. Q&A 기록

### Q. "임시 Rust 환경"이란?

작업한 Mac에 Rust가 설치되어 있지 않아, 시스템을 건드리지 않고 검증하기 위해
Rust 도구를 세션 전용 폴더에 격리 설치해 사용했다.

- `RUSTUP_HOME`/`CARGO_HOME` 환경변수로 설치 위치만 바꾼 정식 rustup 설치
- 시스템 PATH·셸 설정 변경 없음, 폴더 삭제로 완전 제거 가능
- **이 저장소 사용자는 각자 Rust를 정식 설치해야 한다** (README 참고)

### Q. Windows/Mac 실행파일 배포는 다른 문제가 있나?

있다. 요약:

| 항목 | 내용 |
|---|---|
| OS별 빌드 | 네이티브 컴파일이라 Mac 빌드는 Windows에서 실행 불가. OS마다 `cargo build --release` 필요 (CI로 자동화 가능) |
| Mac CPU | Apple Silicon(arm64)·Intel(x86_64) 별도. universal binary로 합칠 수도 있음 |
| macOS 보안 | 서명·공증 없으면 "확인되지 않은 개발자" 경고. 공증엔 유료 Apple 개발자 계정 필요 |
| Windows 보안 | 코드 서명 없으면 SmartScreen 경고 가능 |
| 장점 | egui 앱은 런타임 의존성이 거의 없어 실행파일 하나만 복사하면 동작. release 빌드 기준 수 MB |

결론: 개인 학습·포트폴리오 용도는 각 OS에서 빌드해 쓰면 충분하고,
서명 문제는 공개 배포 시점에 고민하면 된다.
