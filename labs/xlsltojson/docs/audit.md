# 테스트와 감사

## 감사 범위

2026-11-13 기준으로 CLI, 브라우저 변환과 편집, 검토 파일, 정적 빌드·로컬 서버, 샘플 데이터, 의존성과 자동 테스트를 확인했습니다. `node_modules`와 `dist`는 생성물로 취급하며 직접 유지보수하지 않습니다. 사용자 입력과 출력 파일은 원본을 보존했습니다.

프로젝트는 Node.js 24.22.3을 기준으로 검증하며 Node 24 계열을 사용합니다. 테스트용 jsdom 31은 프로젝트의 개발 의존성으로 관리합니다. 갱신 후 전체 테스트 31개와 정적 가이드의 파일·HTTP 실행 검사가 통과했습니다.

## 확인 및 보완 사항

- 높음 · SheetJS `xlsx` 0.18.5의 Prototype Pollution과 ReDoS 권고: 공식 배포판 0.20.3으로 고정하고 로컬 정적 자산을 빌드합니다. 갱신 후 `npm audit`에서 보고된 취약점은 0건입니다. [Prototype Pollution 권고](https://github.com/advisories/GHSA-4r6h-8v6p-xvw6) · [ReDoS 권고](https://github.com/advisories/GHSA-5pgg-2g8v-p4x9)
- 높음 · 잘못된 키나 누락된 카드·손패가 내보내질 수 있었음: 가져오기 구조 검사와 내보내기 의미 검증을 분리하고, 수정 가능한 오류는 항목에 표시합니다.
- 중간 · 전략 CLI의 `--sheet`가 무시되고 빈 행 뒤 원본 행 번호가 어긋날 수 있었음: CLI와 웹이 같은 변환 함수를 사용하고 시트와 행 위치를 검증합니다.
- 중간 · 비정상 우선순위가 0 또는 잘린 값으로 바뀌고 정규화된 열 이름이 중복될 수 있었음: 명시적인 오류로 처리합니다.
- 중간 · 파일을 읽는 동안 다른 파일을 고르거나 편집하면 이전 결과가 새 작업을 덮어쓸 수 있었음: 요청 순서와 작업 변경을 확인해 오래된 결과를 적용하지 않습니다.
- 낮음 · 조건 비교 문자열의 구분자가 실제 값과 충돌할 수 있었음: 정렬된 구조 표현으로 비교합니다. 로컬 서버는 JSON MIME과 `nosniff` 헤더를 반환합니다.

제공된 참고 엑셀의 `Q&A` 시트는 변경 전 전략 CLI와 변경 후 공통 변환을 대조했을 때 360개 키와 전체 값이 일치했습니다. `--sheet`를 실제로 적용하고 중복 열·잘못된 우선순위·중복 조건을 오류로 처리하는 부분은 의도된 동작 변경입니다.

## 남은 한계

- 실제 업무 서버의 인증, 저장·반영 API, 배포와 복구 절차는 이 저장소에 없어 검증할 수 없습니다.
- 브라우저에서 엑셀을 메인 스레드로 읽습니다. 매우 크거나 악의적인 파일의 처리 시간과 메모리를 완전히 제한하지 못하므로 신뢰할 수 있는 파일을 사용하고 운영 환경의 제한을 별도 검토해야 합니다.
- 참고 엑셀과 예시 JSON의 항목 및 규칙 차이는 기획 데이터의 확정 문제입니다. 자동으로 누락 항목을 보충하거나 규칙을 추정하지 않습니다.
- 테스트에는 DOM 기반 UI 검증이 포함됩니다. 이 실행 환경에서 실제 브라우저 접근이 불가능하면 시각적·브라우저별 검증은 별도로 수행해야 합니다.

## 반복 검증

```sh
npm test
npm audit
npm run build
npm run docs:build
npm run docs:check
```

변환 테스트는 참고 엑셀, 시트 선택과 행 번호를 확인합니다. 별도 테스트는 JSON 검증·복구, Ruleset 전체 변경의 원자성, 검토 상태, 파일 읽기 경쟁과 독립 가이드의 경로를 검사합니다. `npm audit` 결과는 실행 시점과 공급처의 권고 정보에 따라 달라질 수 있습니다.
