# Strategy Studio

엑셀 또는 기존 전략·오퍼 JSON을 브라우저에서 불러와 문구를 검토하고 JSON으로 내려받는 정적 웹 도구입니다. 파일은 브라우저에서 처리하며 이 프로젝트에는 파일을 업로드하거나 업무 서버를 변경하는 API가 없습니다.

프로젝트 구조, 데이터 형식, 운영과 감사 기록은 [프로젝트 문서](docs/index.md)에서 확인할 수 있습니다. 독립 학습 사이트는 [가이드 열기](docs/html/index.html)에서 시작하며 앱이나 인터넷 연결 없이 실행됩니다.

## 실행 및 배포

이 프로젝트는 Node.js 24.22.3 이상인 24.x를 사용합니다. 프로젝트의 `.nvmrc`에 검증 기준 버전이 기록되어 있습니다. Node.js를 준비한 뒤 이 디렉터리에서 실행합니다.

```sh
npm ci
npm run start
```

출력되는 주소(기본 `http://127.0.0.1:4173`)에서 사용합니다. `PORT` 환경 변수로 미리보기 포트를 바꿀 수 있습니다. 미리보기 서버는 로컬 접근 전용이며 운영용 서버가 아닙니다. 소스 변경 후에는 미리보기 서버를 다시 실행해야 합니다.

```sh
npm test
npm run build
npm run docs:build
npm run docs:check
```

`npm run build`가 `dist/`에 생성하는 파일 전체를 업무용 웹서버의 정적 파일 경로에 배포합니다. XLSX 라이브러리도 빌드 결과에 포함되므로 별도 CDN이 필요하지 않습니다. 빌드 결과의 `.mjs` 파일이 JavaScript MIME 타입으로 제공되는지 확인하세요. 애플리케이션에 자체 로그인이나 권한 제어는 없으므로 접근 제한이 필요하면 기존 업무 서버의 인증을 적용해야 합니다.

## 사용 방법

1. 파일이 없다면 **새 작업 시작**에서 빈 전략·오퍼 구조 또는 내장 예시를 선택합니다. 빈 구조의 Ruleset ID를 비워 두면 `BJ_6D_S17_DAS_NS`가 적용되며, 다른 규칙을 사용할 경우 직접 입력할 수 있습니다. 버전은 확인 후 입력합니다. 내장 예시는 이 프로젝트에 포함된 고정 사본이며 원본 JSON 변경 시 자동 갱신되지 않습니다.
2. 기존 Excel 또는 JSON을 사용하려면 파일을 선택하고 데이터 유형을 확인한 뒤 **데이터 불러오기**를 선택합니다. Excel은 선택한 시트만 읽습니다. 각 행의 `rulesetId` 열 값이 기본 Ruleset ID보다 우선합니다.
3. **항목 추가**로 전략 또는 오퍼의 조건과 문구를 입력합니다. 기존 항목을 선택해 조건과 문구를 수정한 후 **변경 적용**을 누릅니다. 항목의 Ruleset ID를 바꾸면 확인 후 문서의 대표 ID와 모든 항목 키가 함께 바뀝니다. 조건 중복이나 추가 필드 충돌이 있으면 변경이 적용되지 않습니다. 항목을 개별 선택하거나 목록의 체크박스로 여러 항목을 선택해 삭제할 수 있으며 내보내기 전 삭제를 취소할 수 있습니다.
4. 목록의 변경 상태(변경 없음·추가·수정·삭제 예정)와 검토 상태(검토 전·검토 중·검토 완료)를 확인하고 필터링합니다. 검토 상태는 항목을 열어 변경합니다.
5. 필요하면 **기준 JSON 선택**에서 같은 유형의 기존 JSON을 선택합니다. 현재 데이터가 기준에 비해 추가하거나 누락한 키와 조건을 확인할 수 있습니다. 비교는 문구 차이를 표시하지 않습니다.
6. **서비스 JSON 내보내기**로 결과를 내려받아 기존 업무 절차에 따라 반영합니다. **검토 파일 내보내기**는 별도의 `*.review.json` 파일을 생성하며, 다음 작업에서 **검토 파일 불러오기**로 복원할 수 있습니다. 검토 상태는 서비스 JSON에 포함되지 않습니다.

검토 파일은 항목 키와 조건을 기준으로 적용합니다. 동일한 키와 조건이 반복되어 대상을 특정할 수 없거나 파일과 일치하지 않는 항목은 적용하지 않고 그 수를 알립니다. 삭제 예정 항목은 두 내보내기에서 제외됩니다. 변경 중인 항목은 **변경 적용**을 누른 후 내보내세요.

브라우저를 닫거나 새로고침하면 내보내지 않은 작업이 사라집니다. 서비스 JSON과 검토 파일은 각각 따로 저장하며 변경사항이 남아 있으면 페이지 종료나 새 작업 시작 전에 경고합니다. 빈 구조는 최소 한 항목을 추가해야 서비스 JSON으로 내보낼 수 있습니다.

기본 구조는 읽을 수 있으나 값이 누락되거나 키가 잘못된 JSON은 가져온 뒤 항목의 `검증 오류`를 확인해 수정할 수 있습니다. 오류가 남아 있으면 내보내기가 차단됩니다.

### Ruleset ID 작성

새 작업, 엑셀 변환과 항목 편집에서 ID를 직접 입력하거나 **규칙으로 구성**을 선택해 덱 수, 딜러 소프트 17, 스플릿 후 더블과 서렌더를 선택합니다. 폼은 `BJ_6D_S17_DAS_NS` 같은 ID를 만들며, `S17/H17`, `DAS/NDAS`, `NS/LS`를 지원합니다. 다른 ID도 직접 입력할 수 있습니다. 폼이 해석할 수 없는 기존 ID를 폼의 기본값으로 바꾸기 전 확인합니다.

항목에서 Ruleset ID를 변경하면 삭제 예정 항목을 포함한 문서 전체에 적용됩니다. 검토 상태는 작업 중 유지되지만 검토 파일은 항목 키를 기준으로 연결되므로, 변경 후 서비스 JSON과 검토 파일을 각각 다시 내려받으세요.

### 엑셀 변환 시 주의

- 전략 시트는 `PlayerHandType`, `PlayerHand`, `DealerUpcard`, `Action` 또는 `ActionCode`, `Answer`, `Reason` 열을 사용합니다. `decisionWindow`, `priority`, `rulesetId`는 선택 사항입니다. 기존 전략 CLI의 정규화와 중복 우선순위 규칙을 따릅니다.
- 오퍼는 기존 CLI와 같이 표 또는 행 형식을 지원합니다. 참고 엑셀의 `offers` 시트처럼 `choice`가 비고 `Action`에 `No`가 있는 경우 `Action`을 사용합니다. 표 형식에서 `decisionWindow`가 비면 조건을 추가하지 않습니다. 행 형식은 기존 CLI와 같이 `initial`을 사용합니다.
- 첫 행 오프셋은 시트의 맨 위에서 건너뛸 행의 수입니다. 헤더가 없는 행 형식은 첫 데이터 행의 위치에 맞춰 설정합니다. 선택한 시트의 형식이 맞지 않으면 오류에 표시된 행과 값을 확인하세요.
- `input/data.xlsx`는 참고 자료이며 최종 원본인지 확인되지 않았습니다. 이 파일의 `Q&A` 시트는 기존 `basic_strategy.json`보다 20개 키가 적고 `Q&A (2)`는 자동으로 병합하지 않습니다. 내보내기 전 기준 JSON과 비교하세요.
- 참고 엑셀의 `Legend`에는 Late Surrender가 기재되어 있으나 기존 JSON은 `BJ_6D_S17_DAS_NS` 식별자를 사용합니다. 입력할 Ruleset ID와 실제 게임 규칙의 일치 여부를 담당자가 확인해야 합니다. 이 도구는 Legend를 해석해 규칙을 자동으로 결정하지 않습니다.

## 업무 서버 직접 반영 연동

현재는 다운로드만 지원합니다. 웹에서 직접 반영하려면 실제 업무 서버의 인증 및 권한, 저장 위치, 배포 또는 캐시 갱신 방식이 먼저 확인되어야 합니다. 그 환경에 맞춰 서버 측 검증과 쓰기 API, 반영 전 변경 검토, 감사 기록 및 복구 절차를 추가해야 합니다. 프론트엔드에서 서버 파일을 직접 수정하거나 인증 정보를 보관하는 방식은 사용하지 않습니다.
