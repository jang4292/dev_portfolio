/html-css-playground/

작업 내역 보고서 (누적형)

단일 프로젝트(/html-css-playground/)에 누적한 학습/실무 UI 템플릿 작업 내역을 “나중에 한 번에” 확인할 수 있도록 정리한 문서입니다.

목차

1) 운영 규칙 및 품질 기준 2) 누적 산출물 범위(학습 단계) 3) UI 템플릿/화면 모듈 4) 공통 설계 원칙 5) 통합 운영 방식 6) 현재 상태 요약 7) 다음 작업 권장

문서 버전v1.0

파일 규칙index.html / styles.css / assets/

목표누적 실습 + 재사용 가능한 UI 템플릿

1) 운영 규칙 및 품질 기준

1.1 프로젝트 운영 규칙

  • 모든 실습/템플릿은 단일 프로젝트 /html-css-playground/에 누적
  • 파일 구조 고정: index.html + styles.css + assets/

1.2 검증 루틴(매번 수행)

  1. Chrome DevTools로 박스모델/레이아웃 확인
  2. 모바일 뷰포트(320/375/768/1024) 깨짐 체크
  3. 폼 탭 이동(접근성) 확인

2) 누적 산출물 범위(학습 단계 기반)

Ch.01~03 — HTML 기초(블로그 글 템플릿 기반)
  • 문서 구조(doctype/head/meta viewport/title)
  • 텍스트/목록/정의목록(dl/dt/dd), 링크/이미지(img alt), 표(table thead/tbody th caption)
  • 실무 포인트: 정렬/줄바꿈은 CSS로, 표는 데이터용(레이아웃용 금지)
Ch.04 — 폼(로그인/회원가입)
  • form/label(for)/input(email/password/tel/date)/textarea/select
  • required/minlength/maxlength/pattern/placeholder
  • fieldset/legend 그룹핑 + 에러 영역 확보
  • 실무 포인트: label 없는 input 금지, 기본 HTML 검증 + 추후 JS 강화
Ch.05~07 — CSS 기초(토큰/특이성/공통 스타일)
  • 공통 스타일 기반(타이포/링크/버튼)
  • :root CSS 변수(토큰) 습관 확립
  • 선택자/특이성 관리, !important 최소화
Ch.08~09 — 박스 모델 + 레이아웃
  • box-sizing: border-box 전면 적용
  • margin/padding 설계 원칙(임의 증가 금지)
  • position(relative/absolute/fixed/sticky)
  • 깨짐 점검: width/overflow/이미지 고정폭/min-width:0
Ch.10~11 — 시맨틱 + 멀티미디어
  • header/nav/main/section/article/aside/footer 구조 리팩토링
  • video/audio 적용(autoplay 정책 주의)
  • 시맨틱 선택 혼동 케이스 정리(목차 단위 vs 카드 단위 기준 등)
Ch.12~13 — 선택자 심화 + 애니메이션
  • 상태 스타일: hover/focus-visible/active/disabled
  • 가상요소(::before/::after)로 UI 디테일
  • transition 1종 + keyframes 1종
  • prefers-reduced-motion 고려
Ch.14~16 — 반응형 + 미디어쿼리 + Flex
  • 1열 → 2열 → 3열 반응형 구성
  • %/max-width/height:auto, 미디어쿼리 2~3 구간
  • Flex 핵심 + min-width:0(텍스트 깨짐 방지)

3) UI 템플릿/화면 모듈(실무형 누적 목록)

3.1 기본 섹션 템플릿(초기 5종)

  1. 블로그 글 템플릿
  2. 회원가입/로그인 폼
  3. 마케팅 섹션(그라데이션/CTA)
  4. 헤더 고정 + 2단 레이아웃
  5. 반응형 카드 그리드(Flex)

3.2 확장 화면 모듈

  1. 설문/온보딩 위저드(단일 페이지, 기존과 분리)
  2. 가격 플랜 비교 + 결제 옵션 선택
  3. 관리자 목록(테이블) + 필터 패널
  4. 파일 업로드(드래그&드롭) + 미리보기
  5. FAQ/도움말 센터 + 아코디언
  6. 접근성 내비게이션(Skip Link + 현재 위치)

3.3 공통 UI 인프라 컴포넌트

  1. 모달/다이얼로그(<dialog> 기반)
  2. 토스트/알림 센터 + 상태별 스타일 시스템
  3. 캘린더/스케줄 월간 그리드
  4. 프로필/설정 페이지(읽기 전용 + 폼 혼합)

4) 공통 설계 원칙(전 화면 적용)

  • 토큰화: spacing/radius/color/shadow/container를 :root 변수로 관리
  • 클래스 설계: 태그 선택자 남용 금지, 블록/요소 패턴 유지
  • 안 깨지게: min-width:0, overflow-wrap, 이미지 유동 대응
  • 접근성: label-for, focus-visible, aria-live, skip-link, 현재 위치 표시

5) 통합 운영 방식(“한 번에 보기”)

  • index.html 하나에 모든 템플릿을 누적
  • 상단 탭/내비로 “뷰 전환(보고서/템플릿/체크리스트)”
  • 템플릿 페이지는 섹션 단위로 독립 관리(중복 CSS 최소화)

6) 현재 상태 요약

  • HTML/CSS 학습 단계 산출물 → 실무형 UI 모듈로 확장
  • 모달/토스트/캘린더/설정까지 “앱 화면 뼈대” 확보
  • 다음 핵심은 “통합 스위치 + styles.css 공통화(중복 제거)”

7) 다음 작업 권장(우선순위)

  1. index.html 스위치/라우팅 체계 확정(현재 문서는 그 골격 포함)
  2. styles.css 공통 컴포넌트 표준화(버튼/필드/카드/유틸)
  3. 접근성 회귀 테스트 체크리스트 고정(탭 이동/aria-live/모달 포커스)

템플릿 인덱스

누적된 화면/컴포넌트를 “목록 → 설명 → 바로 이동” 형태로 관리합니다. (실제 마크업은 각 섹션에 붙여 넣는 방식)

목록

각 템플릿은 “섹션 단위”로 붙이고, 공통 CSS는 styles.css로 승격합니다.
